# P0.5 — Hardening Phase Design

**Status:** Draft for review
**Date:** 2026-04-21
**Scope:** Close the two known gaps from P0 before P1 starts: (1) test coverage + CI gate, (2) turnkey `/wpa:*` commands driven by shell scripts. Also update plan/spec templates so future phases cannot regress into the same waivers.

---

## 1. Why P0.5 exists

P0 shipped 52 commits of solid foundation, BUT two user-flagged gaps:

1. **Test coverage is ~30 % backend, 0 % frontend.** Only the primitives had strict TDD (crypto, env, password, tokens, auth middleware, audit encode/decode). The **service layer, every route, and the entire React frontend shipped without tests.** The plan itself waived them at Task 7.5 ("pure business logic — no integration tests here"). VISION principle #7 "security posture is a feature" is not backed by CI reality.
2. **`/wpa:*` commands are Markdown-interpreted.** Each command currently tells Claude what to do; execution depends on Claude doing it right every time. That violates the lazy-user principle (`docs/VISION.md` principle #8 + `memory/feedback_lazy_user_principle.md`): operator should type ONE command and get a working install, zero manual verification or intervention.

P0.5 closes both gaps in a single Hardening cycle before any Baileys/AI risk enters the codebase.

---

## 2. Success criteria

A stranger who clones the repo today must be able to:

1. Open Claude Code in the folder, type `/wpa:start-local`, and get: Docker check, port detection, secrets generated, containers up healthy, admin user auto-created, browser opened to the dashboard — **zero prompts**, **under 3 minutes wall-clock**.
2. Open any commit's PR and see CI gate fail if coverage drops below the tier: **90 % statements for security-critical packages, 80 % for the rest of the backend, 70 % for the frontend**.
3. Run `pnpm test` locally and get unit + component (vitest + RTL + msw) pass. Run `pnpm test:e2e` and get Playwright register→login→dashboard→logout pass.
4. Read `docs/superpowers/plans/` template and see a required "Tests" section in every Epic's exit criteria — no more TDD waivers.

---

## 3. Design principles

- **Shell scripts are the contract, Markdown is the wrapper.** Every `/wpa:*` command = `.claude/commands/wpa/<verb>.md` (1-line invocation) + `scripts/wpa/<verb>.sh` (deterministic, bats-tested). Works with or without Claude Code.
- **Pre-flight is magical.** Docker off → offer to start it. Port conflict → auto-shift to next free port + warn. `.env` missing → auto-generate with backup. First user → auto-register admin with strong random password printed once.
- **Backup is sacred.** `MASTER_KEY` written on generation to `~/wpa-master-key-YYYY-MM-DD.txt` AND printed on screen. The lazy user cannot accidentally lose their master key because they skipped a step.
- **CI coverage gate is hard, not soft.** Vitest `thresholds.*` set per package, CI fails red if any floor breached. No opt-out env var.
- **Plan template update is in scope.** Future Epic exit criteria MUST include a test-file inventory. Brainstorming skill's plan writer checks for it.

## 4. Work streams

Four parallel streams covering the two gaps:

### Stream A — Turnkey commands (lazy-user UX)

**Goal:** `/wpa:*` is shell-backed, pre-flight-aware, zero-prompt by default.

- `scripts/wpa/` directory with shared helpers (`_lib/preflight.sh`, `_lib/colors.sh`, `_lib/compose.sh`).
- New `/wpa:start-local` — the headline command. Composes init → pre-flight → up → wait-healthy → create-admin → open-browser.
- Rewrites for existing 7 commands (`init`, `start`, `stop`, `status`, `logs`, `help`, `kill`) as thin shell scripts.
- New `/wpa:deploy` — interactive deploy walk-through (ask target: Railway/Fly/Render/Lightsail/self-VPS; use provider CLI; verify; open URL).
- New `/wpa:update` — pull latest image, migrate, restart.
- New `/wpa:backup` — encrypted dump to configurable path (default `~/wpa-backups/`).
- New `/wpa:restore` — inverse of backup.
- New `/wpa:rotate-key` — re-wrap every user's DEK under a new master key (requires downtime; confirms).
- `bats` framework for script tests in `scripts/wpa/_test/`.

### Stream B — Backend test backfill

**Goal:** every backend source file has a test file meeting the coverage tier.

**Test stack:** vitest (already installed), supertest (already installed), a new `@wpa/test-utils` package that provides `makeTestDb()` (spins Postgres via testcontainers), `makeTestRedis()` (ioredis-mock or miniredis), test fixtures (`seedUser()`, `seedInvitation()`, `withAuth()`).

Source files needing tests (all under `packages/api/src/`):
- `auth/service.ts` — login (valid / wrong password / unknown user / disabled), rotateRefresh (valid / revoked / expired / user-gone), revokeRefresh (valid / unknown token), registerUser (first-user-admin / open-reg / invite-only reject / invite consume).
- `audit/writeAudit.ts` — the DB-call version (not just encode/decode): writes row, includes encrypted details, failures swallowed with log.
- `routes/auth.ts` — supertest end-to-end for every endpoint, including: login rate-limit, refresh cookie rotation, logout audit with + without bearer, me+401, register (all 3 branches).
- `routes/invitations.ts` — admin create + list, non-admin 403, expired invite rejection.
- `routes/kill.ts` — kill sets Redis flag + audit, restore clears + audit.
- `middleware/ratelimit.ts` — fake timer + N+1 request exceeds limit.
- `redis.ts` — connection handling + graceful disconnect.
- `env.ts` — already tested in `@wpa/shared`, just smoke in `@wpa/api`.

Source files under `packages/worker/src/` and `packages/agent/src/`:
- Heartbeat + SIGTERM handling via signal simulation.

### Stream C — Frontend test backfill

**Goal:** every `packages/web/src/` component has RTL + user-event coverage; critical flows have Playwright E2E.

- **RTL + msw (component layer):**
  - `Login.tsx` — valid submit → redirect; invalid submit → error; loading state.
  - `Register.tsx` — password <12 char rejection; invite-token field submission; success → redirect to /login.
  - `RequireAuth.tsx` — unauthenticated → Navigate to /login; authenticated → Outlet.
  - `Shell.tsx` — kill-switch button click behavior; sign-out calls API + clears state.
  - `Dashboard.tsx` — renders json-render `<Renderer>` with placeholder spec without throwing.
  - `api/client.ts` — silent refresh on 401 → retry; final 401 → throw ApiError.
  - `stores/auth.ts` — bootstrap reads refresh cookie → populates me; login/logout state transitions.
- **msw handlers** in `packages/web/src/test/msw/handlers.ts` — mock every `/api/auth/*` endpoint with realistic responses + edge cases.
- **Playwright E2E** in `packages/web/e2e/` — runs against live `docker-compose` (reuses `scripts/wpa/start-local.sh` with a `--e2e` flag that spins isolated ports + DB + test data):
  - `auth-flow.spec.ts` — register first user → auto-admin → login → dashboard → logout → login again.
  - `kill-switch.spec.ts` — admin hits /api/kill → flag set → audit log has entry.
  - `invite-flow.spec.ts` — admin creates invite → second user registers with token → second user NOT admin.

### Stream D — CI gate + templates

**Goal:** coverage can't regress silently; future plans can't waive tests.

- **Vitest coverage thresholds** in each package's `vitest.config.ts`:
  - `@wpa/shared` — 90/85/90 (statements/branches/functions).
  - `@wpa/api` overall 85 with an exception matrix that applies 90 to `src/auth/**` + `src/audit/**` + `src/routes/kill.ts`, 80 to `src/routes/auth.ts` + `src/routes/invitations.ts`.
  - `@wpa/db` — 80 (mostly Prisma glue).
  - `@wpa/worker` + `@wpa/agent` — 80 each.
  - `@wpa/web` — 70 overall, with an exception raising `src/api/client.ts` + `src/stores/auth.ts` to 85 (critical-path).
- **CI `test` job** runs `pnpm test --coverage` and asserts threshold. Hard fail.
- **New CI `test:e2e` job** (`needs: build`) runs `docker compose up -d` + `pnpm --filter @wpa/web exec playwright test`.
- **Plan template:** every Epic's exit criteria block MUST contain `**Tests:** <inventory>`. Brainstorming's writing-plans skill checker rejects plans without it. Documented in `docs/superpowers/plan-template.md`.
- **Spec update:** `docs/superpowers/specs/2026-04-21-whatsapp-personal-assistant-design.md` §7 gains a subsection "Test discipline" pointing here.

## 5. What's in / out of scope

**In scope for P0.5:**
- Test backfill for every P0 source file
- Shell-backed `/wpa:*` commands + new `/wpa:start-local`, `/wpa:deploy`, `/wpa:update`, `/wpa:backup`, `/wpa:restore`, `/wpa:rotate-key`
- bats framework for shell-script tests
- Vitest coverage thresholds + CI gate
- Playwright E2E + `test:e2e` CI job
- `@wpa/test-utils` package (testcontainers-based real Postgres + Redis fakes)
- Plan/spec template updates
- Documentation updates reflecting new turnkey commands

**Out of scope for P0.5 (deferred to P1+):**
- Any Baileys, WhatsApp, AI, or SSE work (that's P1/P2)
- Multi-user install UX polish beyond the admin-auto-create
- Mobile app
- Rule cookbook / Wiki content beyond stubs

## 7. Exit criteria (Hardening DONE when all true)

- [ ] `pnpm test --coverage` green across all packages with the tiered thresholds.
- [ ] `pnpm test:e2e` green against live docker-compose.
- [ ] `/wpa:start-local` runs on a fresh clone, zero prompts, under 3 min, opens browser to registered dashboard.
- [ ] All other `/wpa:*` commands shell-backed + bats-tested.
- [ ] CI gate fails red on coverage regression (verified by deliberately cutting a test and confirming CI red).
- [ ] Plan template (`docs/superpowers/plan-template.md`) requires a **Tests** subsection in every Epic.
- [ ] Spec §7 updated with test-discipline subsection.
- [ ] `docs/INSTALL.md` + `README.md` updated to present `/wpa:start-local` as THE way.
- [ ] A stranger following the README can register + log in in under 3 minutes.

## 8. Risks + mitigations

- **testcontainers in CI is slow.** Mitigation: use Docker layer caching + service containers in GH Actions for `postgres:16-alpine` + `redis:7-alpine`, skip testcontainers locally in favor of docker-compose-already-running check.
- **Playwright flakes in CI.** Mitigation: retry once; use `waitForResponse` and `locator.filter()` patterns; avoid `waitForTimeout`.
- **Coverage thresholds discourage new contributions.** Mitigation: thresholds are per-package, not per-file; contributors can add a new file with its own tests without getting dinged for uncovered-unrelated-code.
- **Master key backup file on disk is a security downgrade vs env-var-only.** Mitigation: `chmod 600`, write to home dir (not repo), and `/wpa:init` suggests moving it to a password manager + deleting. Documented clearly.
