## Epic H2 — `/wpa:start-local` (maximum-magic headline command)

**Files:**
- Create: `scripts/wpa/start-local.sh`
- Create: `scripts/wpa/_test/start-local.bats`
- Modify: `.claude/commands/wpa/start-local.md` (new; thin wrapper)

**Approach:**
- `start-local.sh` orchestrates:
  1. `require_docker` — if Docker not running, offer to start (`open -a Docker` on macOS, `systemctl start docker` on Linux). Wait up to 60s for daemon.
  2. `find_free_port 3000 3001 3002 3003` — pick first free; set `API_PORT`.
  3. `ensure_env_file` — run `first-run.sh` if `.env` absent. Write `MASTER_KEY` backup to `~/wpa-master-key-$(date +%Y-%m-%d).txt` with chmod 600.
  4. Stamp `API_PORT=$port` into `.env` (replace line).
  5. `docker compose up -d --build`.
  6. `wait_for_healthz http://localhost:$port/healthz 90s`.
  7. Create admin via one-shot SQL or POST /api/auth/register: generate strong passphrase via `openssl rand -base64 18 | tr -d '=+/' | cut -c1-24` OR use diceware-style (reuse first-run's password-gen helper). Print once; store NOTHING.
  8. `browser.sh open http://localhost:$port` (uses `open` / `xdg-open` / `start`).
- bats test: spin up a fake `docker` shim that returns success; assert the script's argv structure, env mutations, and final echo output match expectations. Real docker is tested in H12 smoke, not bats.
- Markdown wrapper: `Run bash scripts/wpa/start-local.sh $ARGUMENTS. Summarize the tail if exit != 0.`

**Exit:**
- [ ] `bash scripts/wpa/start-local.sh` on fresh clone (with Docker running) reaches the dashboard in under 3 min, prints admin credentials once, opens browser.
- [ ] bats-assert unit tests: docker-down path prompts to start; port-conflict path shifts to next free; missing-.env path invokes first-run.
- [ ] Commit: `feat(wpa): /wpa:start-local turnkey command`.

- Each `.sh` gets a bats test covering happy path + one failure path.

**Exit:**

- [ ] bats passes for all 7 commands.

## Epic H4 — New commands: `/wpa:deploy` + `/wpa:update` + `/wpa:backup` + `/wpa:restore` + `/wpa:rotate-key`

**Files:**
- Create: `scripts/wpa/{deploy,update,backup,restore,rotate-key}.sh` + bats tests for each
- Create: `.claude/commands/wpa/{deploy,update,backup,restore,rotate-key}.md`

**Approach:**
- `deploy.sh` — interactive target picker (Railway/Fly/Render/Lightsail/self-VPS). Delegates to `deploy/<target>/deploy.sh` (new per-target scripts). Each provider script uses the matching CLI: `railway up`, `flyctl deploy`, `render blueprint launch`, `aws lightsail create-container-service-deployment`. Persists choice to `.wpa-deploy-target` for future `/wpa:update` to know where to redeploy.
- `update.sh` — `docker compose pull && docker compose up -d` for self-host; provider-specific for others.
- `backup.sh` — encrypted DB dump: `pg_dump | openssl enc -aes-256-gcm -k $MASTER_KEY` → timestamped file at `~/wpa-backups/`. Also dumps Redis AOF snapshot.
- `restore.sh` — inverse; requires `MASTER_KEY` match (hash-compare), restores DB + Redis, alerts user to re-pair WhatsApp (P1 concern).
- `rotate-key.sh` — takes new master key, decrypts every `user.encrypted_dek` with old, re-encrypts with new, writes atomically. Prints new key once. Requires downtime; confirms twice.
- bats: every script with a fake-provider/fake-docker shim, assert correct CLI calls + file movements.

**Exit:**
- [ ] All 5 new commands work against at least one real target (dry-run mode acceptable where real deploy would charge money).
- [ ] bats: each command has happy-path + rollback-on-failure tests.
- [ ] Commit one-per-command: `feat(wpa): /wpa:deploy`, `feat(wpa): /wpa:update`, etc.

## Epic H5 — Route tests via supertest

**Files:**
- Create: `packages/api/src/routes/auth.test.ts`, `invitations.test.ts`, `kill.test.ts`
- Modify: `packages/api/vitest.config.ts` to include integration-test setup + coverage config

**Test inventory:**
- `auth.test.ts`:
  - POST /login: valid → 200 + accessToken + refresh cookie; wrong password → 401; unknown email → 401; invalid body → 400; rate-limit after 5 → 429.
  - POST /refresh: valid cookie → rotated tokens; missing cookie → 401; revoked token → 401; expired token → 401.
  - POST /logout: valid session → 204 + audit row; no session + no bearer → 204 + audit row userId=null; valid-bearer-expired → 204 + audit row with sub.
  - GET /me: valid → user; invalid → 401.
  - POST /register: first-user → admin; subsequent invite-required → 403 without token; with valid token → user + invite.used_at set; open-registration on → works without invite.
- `invitations.test.ts`:
  - POST /invitations as admin → 201 + token; as non-admin → 403; unauth → 401.
  - GET /invitations as admin → list; as non-admin → 403.
- `kill.test.ts`:
  - POST /kill → `wpa:global:assistant_reply_enabled=false` in Redis + audit kill; unauth → 401.
  - POST /kill/restore → flag cleared + audit setting_change.

**Approach:**
- Use `@wpa/test-utils` `makeTestDb()` + `makeTestRedis()`. Each test file sets up in `beforeAll`, tears down in `afterAll`. `beforeEach` truncates tables for isolation.

**Exit:**
- [ ] All route tests green.
- [ ] `packages/api` statements coverage for `src/routes/**` ≥ 90.
- [ ] Commit: `test(api): supertest integration tests for all routes`.
