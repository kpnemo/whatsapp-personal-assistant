## Epic PA2 — Worker Baileys integration

**Files:**
- Modify: `packages/worker/package.json` — add `@whiskeysockets/baileys@6.7.x` (exact pin), `qrcode@1.5.x` for PNG emit, `ioredis@5.x`.
- Create: `packages/worker/src/pair/state.ts` — `PairMachine` class, state transitions.
- Create: `packages/worker/src/pair/baileys.ts` — thin wrapper: `makeSocket(authState, onUpdate) → disposer`.
- Create: `packages/worker/src/pair/index.ts` — subscribes to `wpa:pair-cmd`, dispatches into `PairMachine`.
- Modify: `packages/worker/src/index.ts` — wire `pair.start()` into main loop; keep heartbeat.

**Approach:**
- `PairMachine` states: `{idle, generating, awaiting_scan, paired, error, expired}`. Transitions fire on Baileys events (`connection.update`, `creds.update`) and timer (2-min expire).
- Writes QR PNG (base64) to `wpa:pair:{userId}:qr` with EX 30.
- Writes state enum to `wpa:wa-session:{userId}:state`.
- On paired: extracts `state.creds.me.id`, strips `@s.whatsapp.net` suffix → phoneNumber string; hands off to PA3's persistor.
- Does NOT handle `messages.upsert` yet (P1-B). Filter is a no-op.

**Tests:**
- `packages/worker/src/pair/state.test.ts` — exhaustive transition table + timer expiry with vitest fake timers.
- `packages/worker/src/pair/baileys.test.ts` — mock the Baileys `makeWASocket` export; assert our wrapper passes correct options (browser, logger, auth state shape).

**Exit:**
- [ ] `pnpm --filter @wpa/worker build` clean.
- [ ] Unit tests ≥ 90 statements on `state.ts`.
- [ ] Manual: run worker locally with a throwaway phone; scans complete paired; state reaches `paired` within 10 s of scan.

## Epic PA3 — Session persistence

**Files:**
- Create: `packages/worker/src/pair/authStore.ts` — Baileys `AuthenticationState` adapter backed by Redis + encryption helpers from `@wpa/shared`.
- Create: `packages/worker/src/pair/snapshot.ts` — every 15 s + on state transition, flush Redis creds+keys to `WhatsappSession.authState` (encrypted).
- Create: `packages/worker/src/pair/restore.ts` — on worker boot, list `whatsapp_sessions` where `status=paired`, hydrate Redis, auto-reconnect Baileys sockets.
- Modify: `packages/shared/src/crypto.ts` — already has `encryptWithDek`/`decryptWithDek`; reuse, no changes.

**Approach:**
- Redis adapter conforms to Baileys' `AuthenticationCreds` + `SignalKeyStore` interfaces. Each key read/write is ecrypted with the user's DEK (unwrapped once per session into memory, held as long as the socket lives).
- Snapshot runs under a `node:timers/promises` setInterval — cancellable on SIGTERM.
- Restore path: for each paired session row, `decryptWithDek(authState)` → write into Redis keys → `PairMachine.restore(userId)` reopens Baileys socket with state already populated.
- Audit `pair.restored` on successful hydrate.

**Tests:**
- `packages/worker/src/pair/authStore.test.ts` — round-trip creds through encrypt→Redis→decrypt with a real `ioredis-mock`.
- `packages/worker/src/pair/snapshot.test.ts` — fake timers, assert flush cadence + encrypted Postgres write.
- `packages/worker/src/pair/restore.test.ts` — boot-time hydrate path; corrupt blob → audit `pair.failed`, session status=`error`.

**Exit:**
- [ ] `docker compose restart app` with an already-paired session keeps pairing — no QR re-scan.
- [ ] `pnpm --filter @wpa/worker test` green.
- [ ] Commit: `feat(worker): persist Baileys auth state Redis + Postgres (encrypted)`.

## Epic PA4 — API pair routes

**Files:**
- Create: `packages/api/src/routes/pair.ts` — three handlers: `init`, `status`, `qr`.
- Create: `packages/api/src/services/pair.ts` — issues pair commands + reads state; owns rate-limit logic.
- Modify: `packages/api/src/app.ts` — mount `pairRouter`.
- Modify: `packages/api/src/middleware/rate-limit.ts` (or create if absent) — Redis `INCR` + EXPIRE helper.

**Approach:**
- `POST /api/pair/init`:
  - `requireAuth` middleware → `userId` on `req`.
  - Check rate: `INCR wpa:pair-rate:{userId}`; if > 3, `429 Retry-After`. On first increment, `EXPIRE 3600`.
  - Upsert `WhatsappSession` (status=pairing).
  - `XADD wpa:pair-cmd * userId {userId} type init` onto stream.
  - Write `AuditLog` (type=pair, subtype=init).
  - Return `201 {sessionId}`.
- `GET /api/pair/status`:
  - Read `wpa:wa-session:{userId}:state` + join session row.
  - If `paired`, decrypt `phoneNumber`.
  - Return `200 {state, sessionId, phoneNumber?, updatedAt}`.
- `GET /api/pair/qr`:
  - Read `wpa:pair:{userId}:qr`. Missing → 404. Present → `image/png` with base64-decoded body.
- Zod schemas for responses (consistency with existing routes).

**Tests:**
- `packages/api/src/routes/pair.test.ts` (supertest via `@wpa/test-utils`):
  - `init` success → 201 + audit row.
  - `init` unauth → 401.
  - `init` over 3/hr → 429 + `Retry-After`.
  - `status` with no session → `{state: "none"}`.
  - `status` when Redis has state=paired → returns decrypted phone.
  - `qr` when key missing → 404.
  - `qr` when key exists → 200 PNG, correct `content-type`.

**Exit:**
- [ ] Route coverage ≥ 90 statements.
- [ ] All 7 test cases green.
- [ ] Commit: `feat(api): /pair/init + /pair/status + /pair/qr with rate limit + audit`.

## Epic PA5 — Web /pair route

**Files:**
- Create: `packages/web/src/routes/Pair.tsx` — the 3-state UI (ToS gate → awaiting-scan → connected).
- Create: `packages/web/src/routes/Pair.test.tsx` (msw mocks for `/api/pair/*`).
- Modify: `packages/web/src/routes/router.tsx` — add `/pair` route under `RequireAuth`.
- Modify: `packages/web/src/components/Shell.tsx` — add "Pair WhatsApp" entry in the nav (disabled if already paired in P1-A — we only allow one session).
- Modify: `packages/web/src/api/client.ts` — add `pair.init()`, `pair.status()`, `pair.qrUrl()` helpers.

**Approach:**
- Render order:
  1. **ToS gate** — full-width banner with the spec's exact ToS text; button `I understand, initialize pairing`.
  2. After click → POST `/api/pair/init`; on 429 show `Retry-After` countdown; on success begin polling.
  3. **Awaiting scan** — `<img src="/api/pair/qr">` (with cache-busting `?t={timestamp}` refreshed every 5 s to get new QRs as they rotate), status ticker polls `/api/pair/status` every 1 s.
  4. **Connected** — ✓ icon, `+phoneNumber`, "Keep this tab open — your device is now linked" message, plus "Disconnect" button (wired in P1-B).
  5. **Error / expired** — retry button that resets to step 1 (counts against rate limit).
- Use TanStack Query for polling with `refetchInterval` to get automatic cleanup on unmount.
- QR `<img>` fetches the byte stream directly — browser handles caching with the query-string bust.

**Tests:**
- `packages/web/src/routes/Pair.test.tsx`:
  - Pre-click state renders ToS banner; button initially enabled.
  - Click + msw 201 → state transitions to awaiting-scan.
  - Click + msw 429 → shows retry countdown.
  - msw status=paired → shows ✓ + phone number.
  - msw status=expired → shows retry button.
  - QR `<img>` requests include cache-buster query.

**Exit:**
- [ ] Web coverage ≥ 75 statements, ≥ 85 for `Pair.tsx`.
- [ ] Commit: `feat(web): /pair route with ToS gate + QR + polling`.
